# Луна — музичні плейлисти

Фінальний проєкт із React, варіант № 9 (Music Playlist). Застосунок шукає композиції через iTunes Search API, дозволяє додавати їх до обраного та створювати власні плейлисти. Тестування виконано за вимогами лабораторної роботи № 8 на цьому ж музичному застосунку.

## Запуск

Потрібні Node.js 24 і npm. Команди виконуйте з кореневої папки проєкту (`finalproject` локально або `luna` після клонування):

```bash
npm ci
npm run dev
```

Відкрийте адресу, яку виведе Vite. Типовий порт — `5173`; якщо він зайнятий, Vite вибере наступний.

У Windows PowerShell, якщо політика виконання блокує `npm.ps1`, використовуйте `npm.cmd` замість `npm`:

```powershell
npm.cmd ci
npm.cmd run dev
```

Ключ API та файл `.env` не потрібні. Для пошуку потрібен доступ до інтернету. Обране й збережені плейлисти доступні в бібліотеці без нових запитів до API.

## Можливості

- Пошук за назвою композиції, виконавцем або альбомом із відправленням форми.
- Початкова добірка з 25 композицій за запитом «Океан Ельзи» та кнопки швидкого пошуку.
- Назва, виконавець, альбом, обкладинка й тривалість композиції. Відсутню обкладинку замінює піктограма.
- Додавання до обраного та видалення з нього.
- Створення плейлиста з назвою та описом, редагування і видалення з підтвердженням.
- Додавання композицій до вибраного плейлиста без дублікатів і видалення з добірки.
- Підрахунок композицій та загальної тривалості плейлиста.
- Збереження бібліотеки в LocalStorage та відновлення після перезавантаження.
- Стани завантаження, помилки, порожньої відповіді та повторний запит.
- Адаптивний інтерфейс українською, підписи кнопок для допоміжних технологій і керування з клавіатури.

Прослуховування відкривається за посиланням на відповідну композицію в iTunes. Застосунок не завантажує аудіофайли.

## Маршрути

| Адреса                   | Сторінка                                       |
| ------------------------ | ---------------------------------------------- |
| `/`                      | Пошук музики та початкова добірка              |
| `/?q=...`                | Пошук із запитом, збереженим в адресі          |
| `/favorites`             | Обране                                         |
| `/playlists`             | Усі плейлисти та форма створення               |
| `/playlists/:playlistId` | Композиції плейлиста, редагування та видалення |
| Інші адреси              | Повідомлення про відсутню сторінку             |

## Архітектура

```text
src/
  components/       Спільні компоненти, форми, картка та списки композицій
  context/          MusicContext: глобальна бібліотека, reducer, LocalStorage
  pages/            Сторінки React Router
  services/         Запити до iTunes API та перетворення відповіді
  utils/            Валідація плейлиста і форматування тривалості
  __tests__/        Компонентні, інтеграційні та API-тести, snapshot
  test/             Налаштування Jest, тестові дані й обгортка провайдерів
  App.jsx           Маршрути та провайдери
  main.jsx          Точка входу
```

`MusicProvider` використовує Context і `useReducer` для спільного стану обраного та плейлистів. `DiscoverPage` піднімає запит із форми й передає його до `ItemList`. Компонент `ItemList` отримує дані через сервіс `searchTracks`, обробляє асинхронні стани та передає композиції до `TrackList`. Кожну композицію відображає окремий `ItemCard`.

Запит надсилається через `fetch`. Після зміни запиту або демонтування компонента `AbortController` скасовує попередній запит. Запізніла відповідь не перезаписує нові результати. Якщо відповідь не надходить протягом 15 секунд, застосунок показує помилку з можливістю повторити пошук.

Назва плейлиста має містити від 2 до 60 символів та бути унікальною без урахування регістру. Опис обмежено 250 символами. Зайві пробіли на початку й наприкінці полів видаляються.

Бібліотека зберігається за ключем `luna-music-library-v1` у поточному браузері та не синхронізується між пристроями. Некоректні збережені записи відкидаються. Якщо браузер забороняє запис або сховище переповнене, інтерфейс показує повідомлення.

## Тестування за ЛР 8

Використано **Jest**, **React Testing Library**, **jest-dom** і **user-event**. Babel перетворює JSX для Jest; середовище `jsdom` надає DOM. Snapshot створюється з DOM через `asFragment()`, тому `react-test-renderer` не потрібний.

```bash
npm test
npm run test:coverage
npm run test:watch
```

Тести не залежать від доступності iTunes: компоненти використовують `jest.mock()` для API-сервісу, а тести сервісу підміняють `fetch` через `jest.fn()`.

| Вимога ЛР 8                  | Перевірка                                                     |
| ---------------------------- | ------------------------------------------------------------- |
| Рендеринг списку без помилок | `ItemList.test.jsx`                                           |
| Потрібна кількість елементів | Рівно 5 композицій із тестових даних                          |
| Асинхронне завантаження      | «Завантаження...» до завершення керованого Promise            |
| Помилка                      | «Помилка завантаження даних» після відхиленого запиту         |
| Snapshot                     | DOM картки `ItemCard`, файл у `__snapshots__/`                |
| Пошук                        | Оновлення списку після введення та відправлення нового запиту |

Додаткові тести перевіряють повторний запит, порожню відповідь, таймаут, запізнілі відповіді, HTTP- і мережеві помилки, перетворення API-даних, обране, плейлисти, валідацію, маршрути та LocalStorage.

Результат перевірки: **33 тести у 5 наборах і 1 snapshot проходять**. Покриття рядків коду — **93,05%**. Звіт після `npm run test:coverage` доступний у `coverage/lcov-report/index.html`.

Snapshot зберігається разом із кодом. Оновлюйте його лише після перевірки очікуваних змін:

```bash
npm test -- --updateSnapshot
```

## Збірка та форматування

```bash
npm run build
npm run preview
npm run format:check
```

Готова збірка міститься в `dist/`. Команда `npm run format` застосовує єдиний стиль до коду. Налаштування Prettier зберігаються в `.prettierrc.json`.

## Публікація

Проєкт містить `netlify.toml` і `vercel.json` для збірки та обробки вкладених маршрутів SPA. Публікація сайту потребує облікового запису на обраній платформі. Сайт поки не розгорнуто.

### GitHub

Репозиторій: [dox228337/luna](https://github.com/dox228337/luna). Для клонування потрібен доступ до репозиторію:

```bash
git clone https://github.com/dox228337/luna.git
cd luna
npm ci
npm run dev
```

`node_modules`, `dist`, звіти покриття та локальні файли платформ виключені через `.gitignore`.

### Netlify

Імпортуйте GitHub-репозиторій. Якщо репозиторій містить лише цей проєкт, залиште кореневу папку без змін; якщо весь навчальний workspace — виберіть `finalproject`. Команда збірки: `npm run build`, папка результату: `dist`. Файл `netlify.toml` задає Node.js 24 і перенаправлення маршрутів на `index.html`.

### Vercel

Імпортуйте GitHub-репозиторій, виберіть кореневу папку проєкту та шаблон Vite. Команда збірки: `npm run build`, папка результату: `dist`. Оберіть Node.js 24. Налаштування маршрутів містяться у `vercel.json`.

Після публікації перевірте пряме відкриття `/favorites` і перезавантаження сторінки плейлиста. До матеріалів здачі потрібно додати фактичні посилання на ваш репозиторій і сайт.

## План демонстрації проєкту

1. Пояснити тему № 9 та показати головну сторінку.
2. Знайти виконавця й показати список композицій із API.
3. Додати композицію до обраного та перейти на відповідну сторінку.
4. Створити плейлист, додати музику, змінити назву й опис.
5. Перезавантажити сторінку та показати відновлення бібліотеки.
6. Пояснити Context, reducer, підйом стану, маршрути й обробку API-помилок.
7. Запустити `npm test`, показати snapshot і звіт покриття.
